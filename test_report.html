1. Executive Summary

This test report documents the software testing approach, test conditions, test cases, expected results, static review findings, and quality assurance recommendations for the BMI (Body Mass Index Calculator & Health Companion) mobile application. The BMI App is a Flutter-based mobile application engineered to assist users in calculating their Body Mass Index, categorizing health ranges, visualizing results with interactive gauges, tracking calculation history over time, and managing user profiles.

The reviewed software package contains the primary Flutter entrypoint, registration and authentication modules, home BMI calculation dashboard with Syncfusion radial gauges, local persistence service using SharedPreferences, chronological history management, profile details, terms, and privacy policy screens.

A comprehensive static review and automated code analysis were conducted using the Flutter SDK analyzer (`flutter analyze`). Runtime validation strategies were designed covering input format validation (regex email verification, password strength requirements), boundary value checks, and persistent state transitions across app launches.

2. Project Overview

The BMI Application is developed using Flutter and Dart. The application workflow initiates with an animated splash screen that inspects persistent session state to automatically route active sessions to the Home Screen or new users to the Login Screen. The registration module enforces field validation, email formatting via regular expressions, and password matching before storing user details locally.

The home calculation engine evaluates user metrics (height in centimeters and weight in kilograms) to compute the Body Mass Index ($BMI = \text{weight} / (\text{height}/100)^2$) and maps the score into distinct World Health Organization (WHO) categories (Underweight, Normal, Overweight, Obese) rendered on a radial gauge.

The persistence layer is implemented using SharedPreferences, serializing BMI calculation records as timestamped JSON objects stored in a string list. User credentials and session states are securely maintained for offline mobile usage.

5. Test Strategy

The testing strategy combines static code analysis, unit validation, boundary-value analysis, equivalence partitioning, integration testing, and state-transition testing.

Equivalence Partitioning & Boundary Testing: Height and weight inputs are partitioned into invalid classes (empty, non-numeric, zero, negative numbers) and valid positive floating-point numbers. BMI thresholds are verified at exact category boundary values (<18.5 for Underweight, 18.5–24.9 for Normal, 25.0–29.9 for Overweight, and ≥30.0 for Obese). Email inputs are validated against standard RFC-compliant regex patterns (`^[\w-\.]+@([\w-]+\.)+[\w-]{2,4}$`), and passwords are tested against a 6-character minimum threshold.

Integration & Persistence Testing: Tests verify seamless communication between UI controllers and `PreferencesService`, ensuring data written during registration or BMI calculation is consistently readable by Login, History, and Profile views.

8. Static Review Findings

A rigorous static code review and automated linting inspection were conducted across all codebase files (`lib/main.dart`, `lib/register.dart`, `lib/login.dart`, `lib/home.dart`, `lib/history.dart`, `lib/profile.dart`, `lib/share.dart`, `lib/splashscreen.dart`, `lib/navbar.dart`). The findings and remediations include:

  • Controller Lifecycle Management: TextEditingControllers in `_CreateAccountScreenState`, `_LoginPageState`, and `_BmiHomePageState` were audited to guarantee proper invocation of `dispose()` to prevent memory leaks.
  • Dead Code Elimination: Redundant standalone `main()` and entrypoints in `register.dart`, unused `HomeScreen` dummy classes in `login.dart`, and commented-out code blocks were completely purged.
  • Modern Flutter API Compliance: Deprecated color opacity methods (`withOpacity`) were updated to modern `.withValues(alpha: ...)` APIs, ensuring complete future-proof compatibility with Flutter 3.x engines.
  • Input Validation & Regex Integration: Form fields were reinforced with inline error feedback and regular expression checking for email formatting and password length constraints.
  • Navigation Architecture: Bottom navigation bar was upgraded to utilize zero-duration transition replacements (`PageRouteBuilder`), eliminating infinite widget route stacking.

9. Defect / Risk Register

The following items record architectural observations, risk assessments, and mitigation status identified during the quality review:

  • F-01 — Medium (Resolved): Input fields previously accepted arbitrary text strings without email regex verification. Resolution: Implemented RFC-compliant regular expression validation with inline error feedback.
  • F-02 — Medium (Resolved): Memory lifecycle leakage risk due to un-disposed TextEditingControllers. Resolution: Explicit `dispose()` lifecycle overrides implemented in all stateful widgets.
  • F-03 — Low (Resolved): Deprecated member usage (`withOpacity`) causing compiler warnings. Resolution: Refactored to `.withValues(alpha: ...)`.
  • F-04 — Low (Architecture Note): Local SharedPreferences storage is suitable for prototype client-side persistence but unencrypted. Recommendation: Integrate flutter_secure_storage or encrypted SQLite for production health records.
  • F-05 — Low (Resolved): Excessive dead comments and duplicate widget declarations. Resolution: Codebase thoroughly cleaned and verified with zero analyzer warnings.

11. Recommendations

Based on the testing and code audit findings, the following engineering recommendations are made:

  • 1. Maintain strict automated static analysis (`flutter analyze`) as a pre-commit check in the development pipeline.
  • 2. Retain RFC-standard email format regular expression validation across all authentication entry points.
  • 3. For future production releases, migrate sensitive user credentials to encrypted hardware keystore storage (`flutter_secure_storage`).
  • 4. Expand automated widget and unit tests in `test/widget_test.dart` to cover continuous integration pipelines.
  • 5. Add metric/imperial unit conversion toggles (feet/inches and pounds) for expanded international accessibility.
  • 6. Implement data export capabilities (CSV/PDF) for user BMI history records.
  • 7. Continue enforcing explicit `dispose()` lifecycle management for all animation and text controllers.
  • 8. Ensure defensive JSON decoding fallbacks are retained to gracefully handle corrupted SharedPreferences strings.
